# Release audit — v0.9.0

The evidence behind [the v0.9.0 release note](https://github.com/castlemountsendemails/plx-native/blob/prod-0.9.0/docs/release-notes/v0.9.0.md). This is a private build from a fork: the branch `prod-0.9.0` is `rail` at `091df1a0` plus the version bump, a dispatch-only workflow and these two documents, built by GitHub Actions under a tag that does not trigger the publishing release workflow. Nothing was released or published. The section at the bottom is only filled by `release.yml`, which did not run, so it stays a placeholder.

## External compatibility reports known at release time

None. No one other than the owner has run this build.

## Compatibility tiers, and what moved

One television, a 2018 set reporting webOS 4.4, sits in the verified tier for the rail build under the debug id. Every other firmware from webOS 4.0 up is in the starts-and-nothing-further tier, graded only by the firmware check in CI. A static check does not move a playback line.

## Known issues at release, with provenance

- Favorites appear only once their first server has answered in a run, unless a saved name exists. Measured by the owner on the television with the debug build.
- The Watchlist pulse is upstream's white 0.4 second flash. Read from the code; not changed here.
- The access-refused share and deleted-library paths were never exercised on a television.

## Deliberately not done

- No GitHub Release, Homebrew Channel manifest, upstream pull request or rename.
- The LGPL corresponding source asset is not built (`source-asset: false`) because the package is not redistributed.
- No debug files are uploaded to Sentry (`upload-debug-files: false`) and no real telemetry credential is compiled in.
- The host test suite is not a gate of this run; upstream's known host-test failures are not addressed.
